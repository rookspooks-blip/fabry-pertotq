Методическое пособие по коду программы

Разобрана расчётная часть программы: как формулы физики записаны на Python и numpy, как программа сама измеряет характеристики прибора по графикам, какие приёмы позволяют считать картину точно и быстро даже на старом компьютере, как проверяется правильность расчётов. Как устроена программа

Программа написана на Python. Для расчётов используется библиотека numpy (быстрые операции над массивами чисел), для окна и рисования — Qt (PyQt6, а на Windows 7 — PyQt5). Код разделён на модули — файлы, у каждого своя задача (рис. 1). Расчётная часть — это модули physics.py и fmt.py: в них нет ни одной строчки про окно, поэтому их можно проверить и понять отдельно.

Азбука numpy за одну страницу

Всё быстрое в программе держится на одной идее numpy: действие сразу над целым массивом. Цикл Python обрабатывает около десяти миллионов чисел в секунду, а numpy — сотни миллионов, потому что внутренний цикл написан на языке C.

x = np.linspace(0, 1, 5)          # массив [0, 0.25, 0.5, 0.75, 1]
y = np.sin(x) ** 2                # синус и квадрат — сразу для всех пяти чисел
mask = y > 0.2                    # массив True/False: где условие выполнено
idx = np.flatnonzero(mask)        # номера элементов, где True
col = x[:, None]; row = x[None, :]  # столбец 5×1 и строка 1×5
table = col * row                 # «растяжение» (broadcasting): таблица 5×5

Последние две строки — приём broadcasting: numpy сам «растягивает» столбец и строку до таблицы. Им программа считает сразу все пиксели картинки: строка — номера столбцов, столбец — номера строк.

1. Физическая модель

Модуль physics.py повторяет формулы теоретической части лабораторной работы. Соответствие формул и функций — в табл. 2.

1.1. Коэффициент резкости, высота пиков, разность фаз

В peak_transmission стоит max(1.0 - R - A, 0.0): зеркало не может отразить и поглотить больше 100 % света. Если пользователь задаст $R+A>1$, пропускание будет нулевым, а не отрицательным.

Функция принимает и одно число, и целый массив: если lam — массив из тысячи длин волн, вернётся массив из тысячи фаз. Благодаря этому одна и та же формула служит и для графика $T(\lambda)$ (массив длин волн), и для колец (массив углов $\sin\theta$).

1.2. Функция Эйри

«Пропускание считается по формуле Эйри. Она получается сложением бесконечного числа лучей, отражённых между зеркалами: их амплитуды — геометрическая прогрессия со знаменателем $Re^{i\delta}$. В программе формула записана одной строкой и работает сразу для массива точек.»

1.3. Характеристики прибора по формулам

Функция возвращает словарь — набор пар «имя: значение». Ширина пика существует, только если провалы между пиками опускаются ниже половины высоты: $T_{\min}=T_{\max}/(1+F)<T_{\max}/2$, т. е. $F>1$ ($R>0{,}172$). При более плохих зеркалах программа честно пишет прочерк, а не выдумывает число.

1.4. Радиусы колец по точной формуле

Из условия максимума $2d\sqrt{n^2-\sin^2\theta}=m\lambda$ находим $\sin^2\theta=n^2-(ma)^2$, где $a=\lambda/(2d)$. Прямое вычитание двух почти равных чисел ($n^2$ и $(ma)^2$ отличаются в шестом-седьмом знаке) теряет точность. Поэтому разность записана как произведение: $n^2-(ma)^2=(n-ma)(n+ma)=a\,(m_0-m)(n+ma)$, так как $n=am_0$. Множитель $m_0-m$ — небольшое число, и точность сохраняется полностью.

«Радиусы колец по формуле: из условия максимума находим синус угла для каждого порядка, радиус — $r=f\,\mathrm{tg}\,\theta$. Разность квадратов записана как произведение, чтобы не терять точность при вычитании близких чисел.»

2. Измерения «по графику»

Главная особенность программы: она не только считает характеристики по формулам, но и измеряет их по построенным кривым, как экспериментатор по осциллограмме. Совпадение измерения и формулы — проверка правильности всей модели.

2.1. Поиск максимумов с уточнением параболой

Максимум — точка, которая выше левой соседки и не ниже правой: (y[1:-1] > y[:-2]) & (y[1:-1] >= y[2:]). Здесь y[1:-1] — все точки, кроме крайних, y[:-2] — их левые соседки, y[2:] — правые. Сравнение сразу всех точек — одна операция numpy вместо цикла.

Настоящая вершина лежит между точками сетки. Через три точки $(-1,y_{\text{л}})$, $(0,y_{\text{ц}})$, $(1,y_{\text{п}})$ проводят параболу $y=y_{\text{ц}}+bx+ax^2$ с $a=(y_{\text{л}}-2y_{\text{ц}}+y_{\text{п}})/2$, $b=(y_{\text{п}}-y_{\text{л}})/2$. Её вершина (рис. 2)

x^{*}=-\frac{b}{2a}=\frac{1}{2}\,\frac{y_{\text{л}}-y_{\text{п}}}{y_{\text{л}}-2y_{\text{ц}}+y_{\text{п}}},\qquad y^{*}=y_{\text{ц}}-\frac{1}{4}\,(y_{\text{л}}-y_{\text{п}})\,x^{*}.

Именно это записано в строках с bend и shift. np.divide(..., where=bend != 0) защищает от деления на ноль, если три точки лежат на прямой.

2.2. Расстояние между пиками, ширина, контраст

Порядок действий: найти все максимумы; выбрать два соседних вокруг $\lambda_1$ (np.searchsorted находит место $\lambda_1$ в упорядоченном списке пиков); их разность — $\Delta\lambda$. Затем у ближайшего к $\lambda_1$ пика ищется уровень половины высоты: последняя точка ниже половины слева и первая справа. Точное место пересечения находится линейной интерполяцией между соседними точками (np.interp). Разность — ширина $w$.

Сколько точек брать? Функция curve_samples требует не меньше 30 точек на ширину пика — тогда ошибка интерполяции меньше сотой доли процента. Измерение идёт только в окрестности $\pm1{,}5\,\Delta\lambda$ вокруг $\lambda_1$, поэтому даже при $R=0{,}99$ точек около 28 тысяч.

2.3. Кольца «по картинке»

Здесь три идеи.

1. Равномерно по $u=\sin^2\theta$, а не по радиусу. Фаза $\delta=4\pi d\sqrt{n^2-u}/\lambda$ почти линейна по $u$, а по радиусу — квадратична (кольца сгущаются к краю). Если брать точки равномерно по $u$, на каждое кольцо приходится одинаковое число точек (per_period = 6), и ни одно кольцо не «проскакивает», сколько бы их ни было. При 22 тысячах колец на экране это 130 тысяч точек и 2–3 мс работы.

2. Шесть точек на кольцо достаточно, чтобы найти его. Функция Эйри на каждом периоде имеет ровно один максимум, поэтому среди точек периода всегда есть «вершинка» — точка выше соседей.

3. Уточнение «как в микроскоп». Шести точек мало для точного положения. Поэтому вокруг каждого найденного максимума берутся 33 точки на отрезке $\pm$шаг, из них выбирается лучшая, шаг уменьшается в 16 раз — и так трижды. Итоговая точность — примерно $1/16^3\approx1/4000$ исходного шага: радиусы совпадают с формулой до пяти знаков. Уточняются сразу все кольца одним действием numpy над таблицей «кольца × 33 точки» (center[:, None] + step * offsets[None, :]).

«Кольца программа находит сама: проходит яркость от центра к краю, шагая равномерно по квадрату синуса угла, — тогда на каждое кольцо приходится одинаково точек, и ни одно не теряется. Каждый найденный максимум уточняется тремя увеличениями, и радиусы совпадают с формулой до пяти знаков.»

3. Точные формулы для быстрой картинки

Картинку на экране можно было бы строить «в лоб»: посчитать пропускание в миллионе точек и нарисовать. Так делала первая версия программы; в тяжёлых режимах (тысячи колец, $R=0{,}99$) это занимало до 350 мс на кадр. Вторая версия использует два математических приёма и тратит около 10 мс при любых параметрах.

3.1. Наибольшее и наименьшее значение в столбце пикселей

На экране кривая рисуется столбцами пикселей. Для каждого столбца нужно знать только две вещи: где кривая в этом столбце выше всего и где ниже всего (рис. 3). Для функции Эйри это известно без перебора точек: если внутри отрезка фаз $[\delta_a,\delta_b]$ есть $\delta=2\pi m$, наибольшее значение равно $T_{\max}$; если есть $\delta=\pi(2m+1)$, наименьшее равно $T_{\max}/(1+F)$; иначе крайние значения — на концах отрезка, потому что между пиком и провалом функция монотонна.

Проверка «есть ли $2\pi m$ на отрезке $[a,b]$»: берём ближайшее снизу к $b$ кратное $2\pi$ — np.floor(b / period) * period — и смотрим, не меньше ли оно $a$. Вся функция — десяток действий numpy над массивом из тысячи столбцов: доли миллисекунды.

3.2. Средняя яркость пикселя через первообразную

Пиксель картины колец покрывает интервал радиусов, внутри которого у края экрана помещаются десятки тонких колец. Если взять яркость в одной точке пикселя, получится муар — ложные узоры. Правильно брать среднее по пикселю:

\bar T=\frac{1}{\delta_2-\delta_1}\int_{\delta_1}^{\delta_2}\frac{T_{\max}\,d\delta}{1+F\,\sin^{2}(\delta/2)}.

У функции Эйри есть первообразная. Подстановка $t=\mathrm{tg}(\delta/2)$ даёт на одном периоде $(-\pi,\pi)$

\int\frac{d\delta}{1+F\,\sin^{2}(\delta/2)}=\frac{2}{\sqrt{1+F}}\;\mathrm{arctg}\!\left(\sqrt{1+F}\,\mathrm{tg}\frac{\delta}{2}\right).

Арктангенс «сбрасывается» на каждом периоде, поэтому непрерывная первообразная $G(\delta)$ собирается так: $\delta=2\pi k+\varphi$, $\varphi\in[-\pi,\pi)$, и за каждый полный период прибавляется $2\pi/\sqrt{1+F}$ (рис. 4):

G(\delta)=\frac{2}{\sqrt{1+F}}\left(\pi k+\mathrm{arctg}\!\left(\sqrt{1+F}\,\mathrm{tg}\frac{\varphi}{2}\right)\right), \qquad \bar T=T_{\max}\,\frac{G(\delta_2)-G(\delta_1)}{\delta_2-\delta_1}.

Тонкие места. Фазы $\delta$ бывают порядка $10^6$ радиан, а нужна разность двух близких значений $G$. Поэтому целая часть $\pi(k_2-k_1)$ и дробная $a_2-a_1$ вычитаются отдельно — так не теряется точность. Если пиксель попал в центр картины, где фаза почти не меняется ($|\delta_2-\delta_1|<10^{-9}$), вместо деления на почти ноль берётся значение в середине.

Проверка: за целый период среднее равно $1/\sqrt{1+F}$ — это известное среднее пропускание интерферометра.

«Яркость пикселя — среднее по пикселю, иначе на тонких кольцах появляется муар. Среднее считается точно, через первообразную функции Эйри: одна формула на пиксель вместо сотен точек. Поэтому картинка строится за миллисекунды при любом числе колец.»

3.3. Анимация зеркала без скачков

Анимация двигает зеркало от 0 до 1000 нм и начинает сначала. Если просто вернуться в 0, картинка скачком изменится. Но через каждые $\lambda/(2n)$ картина повторяется (порядок в центре меняется ровно на 1). Поэтому цикл обрезается на наибольшем кратном $\lambda/(2n)$ — и переход «конец → начало» незаметен.

3.4. Экран не в фокусе (режим лабораторной)

В лабораторной линза выбирается из набора, а расстояние от линзы до экрана $L$ ставит студент. Пучок шириной $D=10$ мм линза собирает в точку на расстоянии $f$; на экране при $L\ne f$ получается кружок диаметром $D|L-f|/f$. Луч через центр линзы попадает в точку $r=L\,\mathrm{tg}\,\theta$. Яркость точки экрана — среднее картины по этому кружку; программа усредняет по отрезку радиусов $[r-\rho,\ r+\rho]$, и среднее снова даёт первообразная, поэтому расфокусировка не замедляет программу.

3.5. Критерий разрешения по провалу

Две линии одинаковой яркости дают сумму двух пиков; отношение яркости в середине между ними к максимуму — глубина провала. Предел разрешения — такое $\delta\lambda$, при котором провал равен 0,81; его находит rayleigh_limit делением отрезка пополам: 60 шагов, каждый вдвое сужает интервал, в котором лежит ответ. Для функции Эйри получается $\delta\lambda_{\min}\approx1{,}03\,w$.

4. Лабораторная работа: варианты и метод наименьших квадратов

4.1. Варианты со скрытыми величинами

Скрытые значения получаются из номера варианта генератором случайных чисел, «засеянным» строкой "fabry-perot-variant-7". Такой генератор на любом компьютере и в любой версии Python выдаёт одну и ту же последовательность — поэтому вариант 7 у студента и в таблице ответов преподавателя один и тот же, а хранить сами значения нигде не нужно. Параметры задания с кольцами подбираются так, чтобы на экране было не меньше семи колец.

4.2. Прямая по методу наименьших квадратов

Функция реализует формулы (19), (20) лабораторной работы: наклон, свободный член, их стандартные отклонения и доверительные границы с коэффициентом Стьюдента. Для прямой через начало координат число степеней свободы на единицу больше. Проверка в тестах — сравнение с numpy.polyfit.

4.3. Искомая величина по наклону

Каждая ветка — формула из обработки результатов лабораторной, с переводом единиц: например, наклон $\Delta\lambda(1/d)$ в пм·мм равен $10^{-15}$ м². Погрешность пересчитывается по правилу для степени: у $\lambda=\sqrt{2nb}$ относительная погрешность вдвое меньше, чем у $b$.

5. Числа по-русски и деления осей

Число записывается с четырьмя значащими цифрами, десятичной запятой, пробелом между тысячами и настоящим знаком минус «−». Очень большие и малые числа — через степень десяти с надстрочными цифрами: $4{,}708\cdot10^{6}$. Приём: math.floor(math.log10(abs(x))) — порядок числа (сколько цифр до запятой).

Деления осей берутся «круглыми»: шаг 1, 2 или 5, умноженный на степень десяти. Сначала находится «сырой» шаг (ширина диапазона / нужное число делений), затем из кандидатов выбирается ближайший к нему по логарифму: min(…, key=lambda s: abs(math.log(s / raw))).

def test_airy_matches_sum_of_beams():
    R, A = 0.9, 0.01
    delta = np.linspace(0, 4 * np.pi, 2001)
    t = 1 - R - A
    field = t * np.sum([(R * np.exp(1j * delta)) ** k for k in range(800)], axis=0)
    direct = np.abs(field) ** 2
    formula = ph.airy(delta, ph.coefficient_f(R), ph.peak_transmission(R, A))
    assert np.allclose(direct, formula, rtol=1e-9, atol=1e-12)

Здесь амплитуда прошедшего света складывается «по определению» — как сумма 800 лучей с множителем $Re^{i\delta}$ (комплексные числа в Python пишутся с 1j), и результат сравнивается с формулой. $0{,}9^{800}\approx10^{-37}$, так что остальные лучи не влияют.

7. Вопросы на защите

Почему результаты «по графику» и «по формуле» немного различаются?
График — это набор точек; положения пиков уточняются параболой, ширина — линейной интерполяцией. Отличие — сотые доли процента; оно показывает точность численного измерения. Формула (13) для $\Delta\lambda$ сама приближённая ($\lambda^2/2nd$ вместо точной разности $\lambda_{m-1}-\lambda_m$), отсюда отличие в четвёртом знаке.
Зачем нужен numpy?
Он выполняет действия сразу над массивами, в десятки раз быстрее циклов Python. Одна строка airy(phase(x, d, n), F) считает пропускание в десятках тысяч точек.
Как программа не теряет узкие пики на графике?
Для каждого столбца пикселей по формуле находится наибольшее и наименьшее значение пропускания в этом столбце; если в столбце есть пик, наибольшее значение равно $T_{\max}$. Поэтому пик виден при любом масштабе.
Откуда берётся яркость пикселя в картине колец?
Это среднее пропускание по пикселю, посчитанное точно через первообразную функции Эйри.
Как найдены радиусы колец «по картинке»?
Яркость просматривается от центра к краю равномерно по $\sin^2\theta$ (одинаково точек на кольцо), максимумы уточняются тремя последовательными увеличениями. Радиусы совпадают с формулой до пяти знаков.
Что будет, если задать $R+A>1$?
Пропускание станет нулевым: в peak_transmission отрицательное пропускание зеркала заменяется нулём, в окне появится сообщение, что свет не проходит.
Как проверено, что программа считает правильно?
Автоматические тесты сравнивают формулу Эйри с прямым сложением лучей, измерения по графикам — с формулами, быстрые формулы — с расчётом «в лоб» по миллиону точек. Тесты выполняются при каждой сборке на трёх системах.
